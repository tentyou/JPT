# 监盘通作品说明书

## 作品名称

**监盘通——基于 MCP 的资产现场盘点与数字取证平台**

## 项目背景

传统资产监盘通常需要在网页项目列表、在线底稿、电子表格和手机相机之间反复切换。项目人员需要手工筛选“是否盘点”资产、复制项目信息、逐项拍照、整理 PDF，再把结果按项目归档。数据搬运耗时，现场网络不稳定时还容易得到不完整清单。

监盘通通过公司只读 MCP 服务直接取得用户可访问的项目、产权单位、底稿科目、盘点标记和资产明细，在手机上形成可离线使用的完整盘点清单。现场照片、物理元数据、资产关系和 PDF 成果均在本机保存，当前版本不向业务系统回写。

## 主要用户

- 资产评估、评估咨询和复核项目的现场工作人员
- 负责组织批量设备监盘、证据整理和成果交付的项目经理
- 需要核对盘点范围和历史证据的复核人员

## 核心流程

1. 在连接设置中粘贴客户 Token 或完整 MCP 配置，并验证凭据。
2. 从 MCP 项目列表选择项目，完整读取项目、单位、科目和资产数据。
3. 在统一的“盘点资产”清单中按待盘点、已完成、全部、已排除筛选。
4. 单项拍照，或进入批量模式选择多项资产共用一次现场拍摄。
5. 自动记录拍摄时间、定位等物理元数据，并为关联资产分别生成 PDF。
6. 离线复核照片和历史记录，导出项目 ZIP 交由客户上传。

## 功能设计

### MCP 只读同步

App 使用 Streamable HTTP MCP 协议调用 `get_my_projects`、`get_project_context`、`get_project_companies`、`get_company_asset_based_approach_subjects` 和 `get_asset_based_approach_draft_data`。同步采用分页完整性校验和单事务提交：任何一页失败都保留上次完整快照。

Token 使用 Android Keystore 和 AES-GCM 加密，保存在不参与系统备份的设备目录。验证新 Token 成功前不会替换原凭据，日志、导出和测试均不包含 Token。

### 统一资产清单

待盘点清单与台账预览合并为一个入口。普通模式下，盘点范围开关控制资产是否纳入本地任务；批量模式下，复选框仅用于选择本次共用拍摄的资产，避免一个控件承担两种含义。

本地盘点范围会在后续只读同步中保留。远端删除的资产进入历史；重新出现时恢复为待盘点。稳定 UID 只作为数据库、照片、PDF 和远端映射的内部关联键，不向普通用户展示。

### 多资产共用照片

用户可按当前筛选结果批量选择两项以上资产，然后拍摄一次。监盘通优先通过同一文件系统的硬链接让多个资产引用同一物理照片；设备不支持硬链接时自动复制作为兼容方案。每项资产仍生成独立 PDF，也可以继续补拍自己的照片。

### 离线证据与成果

项目完整同步后可断网工作。照片和 PDF 按稳定资产身份保存，重复同步不会丢失已有证据。项目 ZIP 包含盘点表与照片 PDF，便于客户在现有上传流程中自行提交。

## 技术架构

| 层次 | 实现 |
| --- | --- |
| 移动端 | Kotlin、Jetpack Compose、CameraX |
| 本地数据 | Room、事务迁移、Android Keystore |
| 在线连接 | MCP Streamable HTTP、JSON-RPC、SSE |
| 文档处理 | Apache POI、Android PDF 与图片处理 |
| 交付 | Gradle、GitHub Actions、自动 Release |

## 创新点

1. 用标准 MCP 接口替代 WebView 和网页表格抓取，减少页面变化对现场工具的影响。
2. 以完整快照、稳定身份和本地证据保留策略解决弱网与重复同步问题。
3. 将一次现场照片可靠关联多项同场设备，降低批量资产逐项拍照的重复劳动。
4. 将远端业务数据与本地现场修改分离，既提示线上权威信息，也不产生意外回写。
5. 通过自动测试、自动构建和自动 Release 提供可复现的竞赛交付链路。

## 安全与边界

- MCP 调用采用只读工具白名单，写入工具在建立网络连接前即被拒绝。
- 当前版本不自动上传或回写业务系统。
- Wi-Fi 传输地址包含临时配对 Token，服务重启后更新。
- 客户 MCP Token、签名文件、本地数据库和现场照片不进入代码仓库。

## 当前限制与后续方向

- 自动发布的是调试签名 APK，正式分发需要配置企业签名。
- 结构化 ZIP 的最终字段需与客户上传规范共同确认。
- 可继续增加按单位、科目、位置的快捷批量选择，以及共用证据关系清单。
